# 2주차 수업 운영안(실제 운영 결과 및 후속 연계 보강)

---

## 1. 교육 개요

- **교육 기간:** 2026년 7월 27일 ~ 7월 31일
- **교육 시간:** 1일 8시간, 총 40시간
- **교육 환경:** Ubuntu 24.04, ROS 2 Jazzy, OpenMANIPULATOR-X, MoveIt 2, Gazebo Harmonic, Python
- **교육 방식:** 개념 설명 → 강사 시연 → 단계별 코드 작성 → 장비 실습 → 오류 분석 → 미니 프로젝트
- **주간 목표:** 1주차의 ROS 2 통신·TF2·URDF/Xacro 지식을 실제 로봇팔 제어, MoveIt Planning Scene, Gazebo 모델·센서 구성으로 확장하고 3주차 비전·3D 환경 인식 수업의 기반을 완성한다.

2주차 전반부에는 실제 OpenMANIPULATOR-X 연결, `ros2_control`, 관절 궤적 및 그리퍼 제어, 동작 티칭과 재생을 진행하였다. 중반에는 MoveItPy를 이용한 경로 계획, Planning Scene, 충돌 회피, 물체 부착 기반 Pick and Place를 구현하였다. 후반에는 Gazebo Harmonic의 월드·모델·플러그인·브리지·카메라 센서를 직접 구성하였다.

## 2. 전체 학습 흐름

```text
OpenMANIPULATOR-X 하드웨어 연결
        ↓
ros2_control과 JointTrajectory·Gripper Action
        ↓
Joint State 기록·Teaching·Playback
        ↓
MoveItPy·RobotState·PlanningComponent
        ↓
Planning Scene·CollisionObject·Attach/Detach
        ↓
Gazebo World·SDF Model·Plugin·Bridge
        ↓
Camera Image·CameraInfo·TF
        ↓
3주차 OpenCV·YOLO·Metric Depth·TSDF 기반
```

## 3. 실제 달성 목표

- OpenMANIPULATOR-X의 하드웨어 연결 상태와 DYNAMIXEL 구성을 확인한다.
- `robot_state_publisher`, `joint_state_broadcaster`, `joint_trajectory_controller`, `gripper_controller`의 역할을 구분한다.
- `JointTrajectory` Topic과 `GripperCommand` Action을 이용해 로봇팔과 그리퍼를 제어한다.
- `/joint_states`를 기록하고 YAML로 저장·재생한다.
- MoveItPy의 `PlanningComponent`, `RobotState`, SRDF, Planning Scene 구조를 이해한다.
- CollisionObject와 Attached Collision Object를 이용해 충돌 회피와 Pick and Place를 구현한다.
- Gazebo Harmonic에서 World, SDF Model, Plugin, Sensor를 구성한다.
- `ros_gz_bridge`로 Command, Joint State, TF, Image, CameraInfo를 ROS 2와 연결한다.
- OpenMANIPULATOR-X 끝단에 Camera Link와 Optical Frame을 추가한다.
- 3주차의 ArUco, YOLO Segmentation, Metric Depth, TSDF, OctoMap 실습에 사용할 검증 환경을 준비한다.

## 7. 강사용 체크포인트

- 실제 장비와 Gazebo의 Topic·Controller 이름 차이를 명확히 한다.
- Joint Limit, 속도, Gripper 힘을 보수적으로 설정한다.
- MoveIt 시작 상태가 현재 `/joint_states`와 일치하는지 확인한다.
- Attached Object와 그리퍼 Link의 접촉은 Allowed Collision Matrix 또는 형상·Pose를 검토한다.
- Gazebo 모델의 Visual만 보고 Collision이 있다고 가정하지 않는다.
- ArUco Box는 YOLO 기본 Class가 아니라 Pose 기준 물체로 사용한다.
- COCO YOLO 실습에는 병·컵·사과·오렌지처럼 학습 Class와 일치하는 물체를 준비한다.
- 단순 Primitive는 Texture 부족으로 YOLO 검출이 실패할 수 있음을 Domain Gap 사례로 활용한다.
- Camera Image Stamp와 TF Stamp를 유지한다.
