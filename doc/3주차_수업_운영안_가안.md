# 3주차 수업 운영안(가안)

## 1. 교육 개요

- **교육 기간:** 2026년 8월 3일 ~ 8월 7일
- **교육 시간:** 1일 8시간, 총 40시간
- **주요 환경:** Ubuntu 24.04, ROS 2 Jazzy, Python, OpenCV, Gazebo Harmonic, OpenMANIPULATOR-X, MoveIt 2
- **개발 방식:** 핵심 개념 설명 → AI를 활용한 코드 생성 → 실행·오류 분석 → ROS 2와 로봇 시스템 통합
- **주간 목표:** OpenCV 기초, 특징점, DNN, YOLO Segmentation, Metric Depth, TSDF, OctoMap, MoveIt Planning Scene Monitor와 Python Dashboard를 하나의 비전 로봇 시스템으로 연결한다.

3주차 수업은 모든 알고리즘을 처음부터 구현하는 방식보다 핵심 원리와 대표 API를 이해하고, 생성형 AI를 이용해 코드 초안을 만든 뒤 실행·수정·검증하는 데 중점을 둔다.

이번 운영안에서는 영상 인식 모델과 실습 물체의 적합성을 함께 고려한다. 기본 COCO YOLO 모델로 검출하기 쉬운 병·컵·사과·오렌지와 같은 물체는 사전학습 모델 실습에 사용하고, 빨간 공은 HSV·Hough 방식, ArUco가 부착된 상자는 ArUco Pose Estimation을 사용한다. 일반 박스·블록은 YOLO-World·SAM2 또는 Custom YOLO Segmentation 프로젝트로 확장한다.

## 3. 수업 운영 원칙

- 알고리즘의 수학적 구현보다 입력·출력·파라미터·장단점·적용 조건을 우선한다.
- 20~40분 단위의 짧은 예제로 여러 기술을 비교한다.
- 강사는 기본 ROS 2 Node와 실행 템플릿을 제공한다.
- 교육생은 AI를 활용해 코드를 생성하고 자신의 Topic·Frame·Message Type에 맞게 수정한다.
- AI 생성 코드에서 ROS 1 혼입, 존재하지 않는 API, BGR/RGB 오류, TF 방향 오류와 Thread 충돌을 직접 찾아 수정한다.
- 영상에 물체가 보인다고 해서 기본 YOLO가 모두 검출하는 것은 아니라는 점을 강조한다.
- 모델의 학습 Class와 실습 물체를 먼저 비교한 뒤 검출 방법을 선택한다.
- 실제 로봇 적용 전 Gazebo와 RViz에서 검증한다.
- 단안 Depth와 영상 인식은 안전 장치가 아니라 경로 계획 보조 정보로 사용한다.

## 4. 실습 물체와 인식 방법 선정

### 4.1 기본 COCO YOLO Segmentation 실습 물체

기본 사전학습 Segmentation 모델로 실습하기 좋은 물체는 다음과 같다.

```text
1순위: bottle, cup, apple, orange
2순위: sports ball, bowl, remote, carrot
3순위: banana, scissors, toothbrush, book
```

권장 실물 조건:

- 불투명한 플라스틱 모형
- 가로·세로 약 4~10 cm
- 높이 약 5~15 cm
- 가능한 한 100 g 이하
- 반사·투명 재질 제외

### 4.2 빨간 공

단색 빨간 공은 COCO의 `sports ball` 클래스와 외형이 달라 기본 YOLO로 안정적으로 검출되지 않을 수 있다.

```text
검출: HSV + Contour + Hough Circle
Mask: HSV Mask
Depth: Depth Anything V2 또는 MoGe-2
MoveIt: Sphere 또는 Box CollisionObject
```

YOLO 결과는 비교 실험으로만 사용한다.

### 4.3 ArUco가 부착된 상자

COCO 기본 클래스에는 일반 박스나 ArUco 박스가 없다.

```text
ArUco 검출
    ↓
solvePnP
    ↓
6D Pose
    ↓
알려진 상자 크기
    ↓
MoveIt CollisionObject
```

ArUco 결과는 Metric Depth와 Custom YOLO 결과의 정확도를 비교하는 기준값으로 활용한다.

### 4.4 일반 박스와 블록

다음 중 하나를 선택한다.

- YOLO-World로 `cardboard box`, `wooden block` 검출
- YOLO-World Box를 SAM2 Prompt로 전달해 Mask 생성
- Grounded SAM2 사용
- Gazebo 합성 데이터와 실제 영상을 이용한 Custom YOLO Segmentation 학습

## 8. 수업 운영 시 조정 기준

- 기본 YOLO가 Gazebo Primitive를 검출하지 못하면 Domain Gap 사례로 설명하고 실물 영상 또는 YCB Texture 모델로 전환한다.
- 빨간 공은 YOLO 성공 여부와 관계없이 HSV·Hough 실습을 우선한다.
- ArUco 상자는 YOLO 대신 solvePnP 기반 Pose를 기본 구현으로 한다.
- Metric Depth 추론이 느리면 2~5 Hz로 낮추고 영상 표시와 분리한다.
- MoGe-2 실행이 어려우면 Depth Anything V2를 필수 과정으로 유지하고 MoGe-2는 시연으로 조정한다.
- TSDF가 불안정하면 저장된 RGB·Depth·TF Dataset으로 Offline Integration을 수행한다.
- Dashboard는 영상 Streaming, 상태 조회, Stop 버튼을 필수 기능으로 둔다.
- 실제 로봇에서는 낮은 속도, 충분한 Padding과 Emergency Stop을 적용한다.

## 9. 4주차 프로젝트 연계

3주차 마지막에는 팀별로 다음 중 하나를 선택한다.

- COCO 생활 물체 기반 Pick and Place
- 빨간 공 추적과 거리 유지
- ArUco 상자 기반 정확한 장애물 회피
- YOLO-World + SAM2 일반 물체 탐색
- Gazebo 합성 데이터 기반 Custom YOLO 학습
- Robot TF + TSDF 작업 공간 스캐너
- 정적 OctoMap과 동적 CollisionObject 혼합 작업 셀

프로젝트 제안서에는 반드시 다음 내용을 포함한다.

1. 사용할 물체와 실제 크기
2. 검출 모델의 학습 Class 포함 여부
3. Gazebo와 실물 자산 확보 방법
4. 검출·Depth·TF·MoveIt 처리 흐름
5. 최소 구현 범위와 확장 범위
6. 실패 시 대체 알고리즘
7. 실제 로봇 안전 운용 방법

이 운영안은 기본 YOLO 모델을 모든 물체에 무리하게 적용하지 않고, 물체의 특성과 학습 Class에 따라 YOLO Segmentation, HSV·Hough, ArUco, YOLO-World·SAM2, Custom 학습을 선택하도록 구성한다. 이를 통해 교육생은 단순 모델 사용을 넘어 실제 로봇 시스템에서 적절한 인식 방법을 설계하고 MoveIt Planning Scene에 통합하는 과정을 경험한다.
