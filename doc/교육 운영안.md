## ros2_control 구성 이해

실습에서는 다음 Controller의 역할을 확인한다.

| Controller | 역할 |
| --- | --- |
| `joint_state_broadcaster` | 각 Joint의 Position·Velocity·Effort 상태 발행 |
| `arm_controller` | Arm Joint의 Joint Trajectory 실행 |
| `gripper_controller` | Gripper Position Action 실행 |
| `robot_state_publisher` | `/joint_states`와 URDF를 이용해 TF 발행 |

확인 명령:

```bash
ros2 control list_controllers
ros2 topic echo /joint_states
ros2 action list
ros2 topic list
```

# 4. 3주차: OpenCV·AI 비전·3차원 환경 인식과 MoveIt 통합

## 3주차 운영 목표

- OpenCV의 기본 영상처리와 특징점 기술을 폭넓게 이해한다.
- 모든 알고리즘을 처음부터 작성하기보다 생성형 AI로 기본 코드를 만들고 직접 실행·검증한다.
- 물체 특성에 따라 HSV, Hough, ArUco, YOLO, SAM 등의 적합한 인식 방식을 선택한다.
- 단안 카메라와 Metric Depth 모델을 결합해 물체 위치를 3차원으로 계산한다.
- Robot TF, TSDF, PointCloud, OctoMap과 MoveIt Planning Scene Monitor를 연결한다.
- FastAPI 또는 pywebview Dashboard를 통해 비전·로봇·환경 상태를 통합한다.

## 실습 물체 선정 원칙

| 물체 | 권장 인식 방식 | 비고 |
| --- | --- | --- |
| 병, 컵, 사과, 오렌지 | COCO 사전학습 YOLO Segmentation | 기본 YOLO 실습에 가장 적합 |
| 무늬가 있는 공 | YOLO `sports ball` 또는 HSV·Hough 비교 | 단색 공은 YOLO 검출 불안정 가능 |
| 단순 빨간 공 | HSV + Contour + Hough Circle | YOLO보다 전통 영상처리가 안정적 |
| ArUco 부착 박스 | ArUco + `solvePnP` | 알려진 크기로 정확한 6D Pose 계산 가능 |
| 일반 박스·나무 블록 | YOLO-World + SAM2 또는 Custom YOLO-Seg | COCO 기본 클래스에 일반 Box가 없음 |
| 작업대·벽·고정 장애물 | Robot TF + Metric Depth + TSDF | PointCloud·OctoMap으로 관리 |

## Gazebo 실습 자산

- 기본 생활 물체는 Gazebo Fuel 또는 YCB Object Set의 병·컵·과일·그릇 모델을 활용한다.
- 모델 확보가 어렵거나 Collision이 불안정하면 Primitive Geometry에 Texture를 적용한다.
- 사각 박스와 블록은 직접 SDF 모델을 제작하고 ArUco 또는 학습용 Texture를 부착한다.
- Custom YOLO 학습 프로젝트에서는 Gazebo Segmentation Camera 또는 Instance ID 영상을 이용해 합성 데이터를 생성한다.
- Gazebo 영상과 실제 영상의 Domain Gap을 줄이기 위해 조명, Texture, 배경, 카메라 Pose와 Noise를 무작위화한다.

# 7. 운영 시 조정 기준

- OpenCV와 AI 모델의 내부 수학을 모두 구현하기보다 주요 입력·출력·파라미터와 적용 조건을 이해하는 데 집중한다.
- AI 생성 코드는 그대로 사용하지 않고 ROS 1 코드 혼입, 존재하지 않는 API, BGR·RGB, Message Type, TF 방향과 Thread 충돌을 검증한다.
- COCO 기본 YOLO가 인식하지 못하는 빨간 공·일반 박스·ArUco 박스를 억지로 같은 모델로 처리하지 않는다.
- 실제 로봇에서는 가볍고 불투명하며 약 4~10 cm 크기의 물체를 사용한다.
- 투명·반사·검정 물체는 Segmentation과 단안 Depth 오차가 크므로 기본 실습에서 제외한다.
- Gazebo 모델은 수업 전에 Scale, Inertia, Collision Geometry와 Texture를 검증한다.
- Metric Depth와 TSDF 결과는 안전 인증 센서가 아니므로 충분한 Collision Padding과 저속 운전을 적용한다.
- 새 장애물이 감지되면 Planning Scene 갱신 외에 실행 중 Trajectory를 중지하거나 취소하는 로직을 별도로 둔다.
- 실제 장비 적용 전에 Gazebo와 RViz에서 먼저 검증한다.
