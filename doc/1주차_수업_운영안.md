# 1주차 수업 운영안

---

교육 기간은 2026년 7월 20일부터 7월 24일까지이다. 목표는 수강생이 Ubuntu 24.04와 ROS 2 Jazzy 개발 환경을 직접 구성하고, 노드 간 통신부터 TF2와 URDF/Xacro 기반 로봇 모델 표현까지 ROS 2의 핵심 흐름을 코드로 구현할 수 있게 만드는 것이다.

## 주간 목표

---

- WSL Ubuntu 24.04, VS Code Remote WSL, Git/GitHub, ROS 2 Jazzy 환경을 구성한다.
- ROS 2의 노드, 토픽, 서비스, 액션, 파라미터 차이를 설명하고 직접 구현한다.
- 사용자 정의 `msg`, `srv`, `action` 인터페이스를 패키지에서 빌드하고 사용한다.
- Launch, namespace, QoS, DDS/RMW가 다중 노드 실행에 미치는 영향을 이해한다.
- TF2로 좌표계를 발행·조회하고 URDF/Xacro 모델을 RViz2에서 확인한다.
- 2주차 OpenMANIPULATOR 실습에 필요한 ROS 2 통신과 로봇 모델링 기반을 갖춘다.

## 차시 운영

---

### Day 1. WSL·ROS 2 환경과 CLI 적응 - 7월 20일

- 핵심 주제: Ubuntu 24.04, Git/GitHub, VS Code Remote WSL, ROS 2 Jazzy 설치, Turtlesim, ROS 2 CLI, RQt
- 실습 자료: `doc/wsl2 가이드.pdf`, `doc/wsl2- ros2 퀵 가이드.pdf`, `doc/ROS2_교재1.pdf`, README의 `ros2 topic pub` 예제
- 실습 산출물: 개인 Git 저장소와 ROS 2 Jazzy 실행 환경, CLI 명령 기록, 원운동하는 Turtlesim 화면
- 확인 질문:
  - 현재 터미널과 작업 파일이 Ubuntu 24.04 WSL 환경에 있는지 설명할 수 있는가
  - 노드, 토픽, 서비스, 인터페이스를 CLI에서 어떻게 조회하는가
  - `rqt_graph`, topic monitor, `topic echo`, `topic hz`는 각각 무엇을 확인하는가

### Day 2. 노드·토픽·패키지와 실행 구조 - 7월 21일

- 핵심 주제: ROS 2 공통 패키지, DDS/RMW, `spin`, 상태, Node/Topic/Service/Action 비교, Python 패키지, Publisher/Subscriber, Header, Launch
- 실습 자료: `gong_ws/src/gong_basic/`, `simple_pub.py`, `class_pub.py`, `class_sub.py`, `header_pub.py`, `mpub.py`, `msub.py`, `mtsub.py`, `m2sub.py`, `tpub.py`, `launch/hello.launch.py`, `launch/mtsubpub.launch.py`
- 실습 산출물: `gong_basic` 패키지, 단일/다중 Publisher·Subscriber, Header 시간 발행, 다섯 노드 Launch 실행 결과
- 확인 질문:
  - `rclpy.spin()`은 노드 실행에서 어떤 역할을 하는가
  - Publisher와 Subscriber의 메시지 타입과 토픽 이름이 일치해야 하는 이유는 무엇인가
  - 여러 노드를 명령별로 실행하는 것과 Launch로 실행하는 것은 어떻게 다른가

### Day 3. QoS·사용자 인터페이스·서비스·파라미터 - 7월 22일

- 핵심 주제: WSL 환경의 DDS 설정, QoS, 사용자 정의 `msg/srv`, Service Server/Client, MultiThreadedExecutor, Parameter callback, AsyncParameterClient, Launch parameter
- 실습 자료: `gong_ws/src/gong_basic/gong_basic/qos_test_pub.py`, `qos_test_sub.py`, `user_int_pub.py`, `service_server.py`, `service_thread_server.py`, `service_client.py`, `my_param.py`, `param_async.py`, `launch/param.launch.py`, `param/*.yaml`, `gong_ws/src/user_interface/msg/UserInt.msg`, `srv/AddAndOdd.srv`
- 실습 산출물: 사용자 메시지 발행, 비동기 서비스 호출, 실행 중 파라미터 변경, YAML 기반 Launch 실행 결과
- 확인 질문:
  - QoS 정책이 맞지 않으면 노드가 실행돼도 통신이 되지 않을 수 있는 이유는 무엇인가
  - 토픽과 서비스는 데이터 흐름과 응답 방식이 어떻게 다른가
  - Parameter callback과 `AsyncParameterClient`는 각각 어느 노드에서 동작하는가

### Day 4. 액션·네임스페이스·TF 발행 - 7월 23일

- 핵심 주제: Action IDL, Fibonacci Action Server/Client, feedback/result, cancel/abort, 스레드 서버, namespace, 다중 Turtlesim, 정적/동적 TF
- 실습 자료: `gong_ws/src/user_interface/action/Fibonacci.action`, `gong_basic/action_server.py`, `action_client.py`, `action_thread_server.py`, `mv_turtle_ns.py`, `launch/two_turtle.launch.py`, `param/turtlesim.yaml`, `tf2_basic/static_turtle_tf2_broadcaster.py`, `dynamic_turtle_tf2_broadcaster.py`
- 실습 산출물: 피드백·취소·중단을 처리하는 Fibonacci Action, namespace가 분리된 두 거북이, 정적/동적 TF 트리
- 확인 질문:
  - Action이 장시간 작업에 적합한 이유는 무엇인가
  - cancel과 abort는 요청 주체와 종료 의미가 어떻게 다른가
  - namespace와 frame 이름은 다중 로봇 환경에서 어떤 충돌을 방지하는가

### Day 5. TF2 조회와 URDF/Xacro 모델링 - 7월 24일

- 핵심 주제: TF2 Listener, transform 조회, Turtlesim TF 추종, URDF 링크·조인트, RViz2, visual/collision/inertial, mesh, Xacro 매크로
- 실습 자료: `gong_ws/src/tf2_basic/tf2_basic/tf_listener.py`, `turtle_tf_listener.py`, `move_u2d2.py`, `launch/urdf_display.launch.py`, `rviz/urdf.rviz`, `urdf/01_myfirst.urdf`~`04_pysics.urdf`, `urdf/04_pysics.urdf.xacro`~`06_macroed.urdf.xacro`, `meshes/`
- 실습 산출물: TF를 따라 움직이는 Turtlesim, RViz2에서 표시되는 다관절 URDF, Xacro로 정리한 로봇 모델, `move_u2d2` 과제 코드
- 확인 질문:
  - TF Broadcaster와 Listener는 각각 무엇을 제공하고 조회하는가
  - URDF의 `origin`, `parent`, `child`, `joint type`이 모델 자세에 어떤 영향을 주는가
  - Xacro를 사용하면 반복되는 링크·조인트 정의를 어떻게 줄일 수 있는가

## 강사용 체크포인트

---

- Day 1에는 모든 수강생이 `ros2 doctor`, Turtlesim, RQt를 직접 실행하고 ROS 2 Jazzy 환경을 확인하게 한다.
- Day 2에는 `colcon build`, `source install/setup.bash`, 실행 파일 등록 과정 중 어느 단계가 빠졌는지 스스로 구분하게 한다.
- Day 3에는 QoS 불일치, 인터페이스 빌드 누락, Service 응답 지연을 의도적으로 재현해 원인을 비교한다.
- Day 4에는 Action의 goal, feedback, result, cancel, abort 흐름을 로그로 남기게 한다.
- Day 5에는 TF 트리와 URDF 링크 트리가 같은 개념이 아님을 구분하고, RViz2의 Fixed Frame 오류를 함께 디버깅한다.
- README의 추가 작업에 기록된 Service, Action, Launch, TF 교안 부재를 2주차 시작 전 보완한다.
- `.gitignore`가 추가됐지만 기존 `__pycache__`와 `.pyc` 파일이 여러 커밋에서 추적되고 있으므로, 향후 제출 기준에서는 생성 파일과 소스 파일을 구분한다.

---
