---

이 문서는 2주차 수업을 확정하기 전에 강사가 교육자료, 소프트웨어, 시뮬레이터, 실기기를 같은 기준으로 준비하고 검증하기 위한 실행 안내서이다. 작성 기준일은 2026년 7월 25일이다.

### 2주차 핵심에서 제외할 자료

- micro-ROS/Pico/servo 교안은 이번 주차의 OpenMANIPULATOR-X·MoveIt 2·Gazebo 목표와 직접 연결되지 않으므로 보충 자료로만 둔다.
- 터틀봇 조립, SLAM, Navigation, 카메라 설치 교안은 2주차 필수 진도에 넣지 않는다.
- Foxy, Humble, Gazebo Classic용 명령을 Jazzy/Harmonic 터미널에서 혼용하지 않는다.

### 필수 소스 저장소

ROBOTIS 공식 Quick Start의 Jazzy 소스 설치 흐름은 다음 네 저장소를 사용한다.

```bash
mkdir -p open_manipulator_ws/src
cd open_manipulator_ws/src

git clone -b jazzy https://github.com/ROBOTIS-GIT/DynamixelSDK.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/dynamixel_interfaces.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/dynamixel_hardware_interface.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/open_manipulator.git
git clone -b jazzy https://github.com/ROBOTIS-GIT/robotis_interfaces.git
```

자료를 확정할 때 각 저장소에서 다음을 기록한다.

```bash
git -C DynamixelSDK rev-parse HEAD
git -C dynamixel_interfaces rev-parse HEAD
git -C dynamixel_hardware_interface rev-parse HEAD
git -C open_manipulator rev-parse HEAD
git -C robotis_interfaces rev-parse HEAD
```

수업 중 upstream 변경으로 결과가 달라지지 않도록 검증한 commit을 강사용 기록에 고정한다. 저장소에 소스를 포함할 경우에는 기존 `gong_ws`와 섞지 말고 별도의 `open_manipulator_ws` 또는 명시적인 `.repos` 파일을 사용한다.

## 4. 준비 및 검증 게이트

---

각 게이트의 명령, 정상 기준, 실패 조치가 모두 기록돼야 다음 단계로 진행한다.

### Gate A. 기본 환경

```bash
source /opt/ros/jazzy/setup.bash

printenv ROS_DISTRO
ros2 pkg prefix rclpy
sudo apt install mesa-utils
glxinfo -B
rviz2
```

#### graphic card 드라이버가  nvidia 가 안 잡히는 경우

- 동일한 Mesa 25.2.8 업데이트에서 Screen 0 does not appear to be DRI3 capable와 llvmpipe 전환이 발생한다는 Ubuntu 버그가 보고돼 있습니다. 이전 Mesa 24.0.5로 되돌리면 가속이 복구됩니다. 아래 명령으로 24.0.5를 설치하고 hold 처리합니다.
```bash
sudo apt update

sudo apt-get install --allow-downgrades \
  libglapi-mesa=24.0.5-1ubuntu1 \
  libgl1-mesa-dri=24.0.5-1ubuntu1 \
  libglx-mesa0=24.0.5-1ubuntu1 \
  libegl-mesa0=24.0.5-1ubuntu1 \
  libgbm1=24.0.5-1ubuntu1 \
  libgbm-dev=24.0.5-1ubuntu1 \
  mesa-vulkan-drivers=24.0.5-1ubuntu1 \
  mesa-va-drivers=24.0.5-1ubuntu1 \
  mesa-vdpau-drivers=24.0.5-1ubuntu1

sudo apt-mark hold \
  libglapi-mesa \
  libgl1-mesa-dri \
  libglx-mesa0 \
  libegl-mesa0 \
  libgbm1 \
  libgbm-dev \
  mesa-vulkan-drivers \
  mesa-va-drivers \
  mesa-vdpau-drivers
```

통과 기준:

- `ROS_DISTRO=jazzy`
- `rclpy` 경로가 `/opt/ros/jazzy` 아래에서 확인됨
- WSLg에서 OpenGL renderer가 확인되고 RViz2가 검은 화면 없이 열림
- OpenGL renderer string: D3D12 (AMD Radeon(TM) Graphics) d3d12 스트링 확인

실패 조치:

- Ubuntu 24.04와 ROS 2 Jazzy 조합을 먼저 복구한다.
- GUI 문제는 Windows GPU 드라이버, WSL 업데이트, WSL 메모리 설정을 확인한다.

### Gate B. OpenMANIPULATOR 소스와 빌드

```bash
cd ~/open_manipulator_ws
source /opt/ros/jazzy/setup.bash

sudo rosdep init          # 최초 1회만 실행
rosdep update
rosdep install --from-paths src -y --ignore-src

colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release
source install/setup.bash
source ~/gong_manipulator_20206/open_manipulator_ws/install/local_setup.bash

ros2 pkg prefix open_manipulator_bringup
ros2 pkg prefix open_manipulator_moveit_config
ros2 pkg prefix open_manipulator_gui
ros2 pkg executables open_manipulator_teleop
```

통과 기준:

- 빌드 실패 패키지 0개
- bringup, MoveIt config, GUI, teleop 패키지 또는 실행 파일 확인
- 새 터미널에서도 두 setup 파일을 source한 뒤 같은 결과 확인

실패 조치:

- `rosdep` 오류와 CMake 오류를 분리해 기록한다.
- Humble 패키지나 과거 `open_manipulator_x_*` 패키지가 overlay에 섞이지 않았는지 확인한다.
- 직접 설치가 교육생 PC별로 불안정하면 ROBOTIS 공식 Jazzy Docker 흐름을 대체 경로로 검증한다.

### Gate C. Description·TF·RViz2

```bash
source /opt/ros/jazzy/setup.bash
source ~/open_manipulator_ws/install/setup.bash

ros2 launch open_manipulator_description open_manipulator_x.launch.py
```

별도 터미널:

```bash
ros2 topic echo /joint_states --once
ros2 run tf2_tools view_frames
```

통과 기준:

- RViz2에 모델과 mesh가 누락 없이 표시됨
- Fixed Frame 오류 없음
- `/joint_states`와 base에서 end-effector까지의 TF chain 확인

실패 조치:

- package share의 mesh 경로, Xacro 파라미터, `robot_description`, Fixed Frame을 순서대로 확인한다.

### Gate D. Gazebo Harmonic 시뮬레이션

```bash
sudo apt-get install ros-${ROS_DISTRO}-ros-gz

source /opt/ros/jazzy/setup.bash
source ~/open_manipulator_ws/install/setup.bash

gz sim --versions
ros2 pkg prefix ros_gz_sim
ros2 launch open_manipulator_bringup open_manipulator_x_gazebo.launch.py
```

별도 터미널:

```bash
ros2 topic echo /clock --once
ros2 topic echo /joint_states --once
ros2 control list_controllers
```

seg fault 오류가 있는경우:
xcb-egl 설정을 해제 하고 GLX+D3D12로 실행 한다.

```bash
unset QT_XCB_GL_INTEGRATION
unset QT_OPENGL
unset MESA_LOADER_DRIVER_OVERRIDE
unset LIBGL_ALWAYS_SOFTWARE
unset LIBGL_ALWAYS_INDIRECT
unset VK_ICD_FILENAMES

export GALLIUM_DRIVER=d3d12
export MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA
```

통과 기준:

- Gazebo Harmonic 실행 및 로봇 모델 표시
- Play 상태에서 `/clock` 증가
- `/joint_states` 수신
- broadcaster와 trajectory controller가 기대 상태로 표시

실패 조치:

- Gazebo Classic 명령이나 `gazebo_ros` 패키지를 사용하지 않았는지 확인한다.
- 창만 열린 경우 Play, controller state, `/clock`, bridge 순서로 확인한다.
- 검은 화면이면 OpenGL renderer와 WSL 자원 할당을 확인한다.

### Gate E. MoveIt 2·teleop·GUI 시뮬레이션

터미널 1:

```bash
ros2 launch open_manipulator_bringup open_manipulator_x_gazebo.launch.py
```

터미널 2:

```bash
ros2 launch open_manipulator_moveit_config open_manipulator_x_moveit.launch.py use_sim:=true
```

터미널 3에서 아래 중 하나만 실행:

```bash
ros2 run open_manipulator_teleop open_manipulator_x_teleop
```

또는

```bash
ros2 launch open_manipulator_gui open_manipulator_x_gui.launch.py
```

통과 기준:

- MoveIt 2에서 현재 상태가 정상으로 표시됨
- `home` 등 안전한 Named State 계획 성공
- 계획 실행 후 Gazebo 관절과 `/joint_states`가 함께 변경됨
- arm과 gripper를 각각 제어 가능

실패 조치:

- teleop과 GUI를 동시에 명령원으로 사용하지 않는다.
- MoveIt start state, controller 이름, action server, simulation Play 상태를 확인한다.

### Gate F. WSL USB와 실기기

Windows 관리자 PowerShell:

```powershell
usbipd list
usbipd bind --busid <BUSID>
usbipd attach --wsl --busid <BUSID>
```

WSL:

```bash
lsusb
ls -l /dev/ttyUSB* /dev/ttyACM*
groups
```

필요한 경우:

```bash
sudo usermod -aG dialout $USER
```

로그아웃 또는 WSL 재시작 후 권한을 다시 확인한다.

실기기 실행 전 체크:

- 로봇 전원 OFF 상태에서 케이블과 관절 시작 자세 확인
- 작업 반경에서 사람과 물체 제거
- 비상 정지 또는 토크 해제 절차 확인
- 포트가 U2D2인지 OpenCR인지 확인
- 첫 동작은 한 관절, 낮은 속도, 작은 범위로 제한

공식 Jazzy 운영 흐름:

```bash
source /opt/ros/jazzy/setup.bash
source ~/open_manipulator_ws/install/setup.bash

ros2 launch open_manipulator_bringup open_manipulator_x.launch.py
```

별도 터미널:

```bash
ros2 topic echo /joint_states --once
ros2 control list_controllers
```

그 다음 MoveIt 2:

```bash
ros2 launch open_manipulator_moveit_config open_manipulator_x_moveit.launch.py
```

통과 기준:

- DYNAMIXEL 통신 오류 없이 bringup 완료
- 실제 관절을 손으로 움직일 때 `/joint_states`가 일관되게 변함
- 안전 Named State의 계획과 저속 실행 성공
- gripper open/close 성공

실패 조치:

- 자세 범위, 전원, 포트, 권한, USB attach, DYNAMIXEL ID와 firmware를 차례로 확인한다.
- 실기기 문제를 해결하는 동안 수업은 Gate E 시뮬레이션으로 진행한다.

## 5. 현재 저장소 코드 사용 주의

---

### 사용할 수 있는 기준 코드

- `gong_basic/action_server.py`, `action_client.py`: Action goal/feedback/result 복습
- `tf2_basic` broadcaster/listener: TF 발행·조회 복습
- `tf2_basic/urdf/`: Xacro와 URDF 파싱 복습
- `tf2_basic/launch/urdf_display.launch.py`: RViz2 모델 표시 복습

### 실기기 제어에 사용하면 안 되는 코드

`tf2_basic/move_u2d2.py`는 이름과 달리 U2D2 통신을 수행하지 않는다. 이 노드는 OpenMANIPULATOR-X와 다른 관절 이름을 사용해 `/joint_states`를 임의 발행하는 시각화용 코드이다. 실제 controller command, DYNAMIXEL hardware interface, 안전 제한을 사용하지 않으므로 실기기 명령원으로 사용하지 않는다.

### 확인된 품질 상태

- `colcon build --symlink-install`: 성공
- Publisher 스모크 실행: 성공
- URDF/Xacro 파싱: 성공
- `colcon test`: 실패
  - 코드 스타일, import 순서, 미사용 import, docstring 규칙 문제가 다수 존재
  - 기능 시험을 대체하는 단위·통합 테스트는 현재 부족

따라서 수업 전 최소한 OpenMANIPULATOR 설치·시뮬레이션·실기기 검증을 별도 체크리스트로 수행하고, “빌드 성공”을 “전체 기능 검증 완료”로 표시하지 않는다.
