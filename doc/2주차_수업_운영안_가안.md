# 2주차 수업 운영안(가안)

---

교육 기간은 2026년 7월 27일부터 7월 31일까지이며, 1일 8시간, 총 40시간으로 운영한다. 목표는 1주차에 학습한 ROS 2 통신, TF2, URDF/Xacro를 OpenMANIPULATOR-X의 `ros2_control`, MoveIt 2, Gazebo Harmonic 실행 구조에 연결하고, 시뮬레이션과 실제 로봇팔에서 같은 관절 상태와 제어 흐름을 확인하는 것이다.

이 문서는 `doc/교육 운영안.md`의 2주차 계획을 수업 단위로 확장한 가안이다. 2026년 7월 25일 현재 OpenMANIPULATOR-X 패키지, Gazebo, U2D2/OpenCR 실기기 검증은 완료되지 않았으므로, `doc/2주차_교육자료_확보_및_작동확인_안내.md`의 준비 게이트를 모두 통과한 뒤 확정안으로 전환한다.

## 주간 목표

---

- OpenMANIPULATOR-X의 링크, 조인트, DYNAMIXEL, U2D2/OpenCR 구성을 설명한다.
- `robot_state_publisher`, `joint_state_broadcaster`, `joint_trajectory_controller`의 역할을 구분한다.
- 키보드 teleop과 GUI에서 관절 및 그리퍼를 제어하고 `/joint_states` 피드백을 확인한다.
- MoveIt 2에서 Planning Group(`arm`, `gripper`), Named State, 계획과 실행의 차이를 설명한다.
- Gazebo Harmonic에서 OpenMANIPULATOR-X를 스폰하고 `use_sim:=true`로 MoveIt 2와 연동한다.
- URDF/Xacro, SDF 월드, 센서·플러그인, ROS-Gazebo 브리지의 관계를 설명한다.
- 실제 로봇과 시뮬레이션의 토픽, 액션, 컨트롤러, 관절 이름을 비교한 검증 기록을 남긴다.

## 운영 원칙

---

- 첫 실행은 반드시 시뮬레이션에서 수행하고, 같은 목표 자세를 낮은 속도로 실기기에 적용한다.
- 실제 로봇 구동 전 시작 자세, 작업 반경, 케이블 간섭, 비상 정지 또는 토크 해제 방법을 확인한다.
- 현재 저장소의 `tf2_basic/move_u2d2.py`는 OpenMANIPULATOR-X 제어 노드가 아니라 임의의 `/joint_states`를 발행하는 1주차 모델 과제이다. 실기기 제어에 사용하지 않는다.
- 기존 `가제보 설치`, `URDF`, `transform` PPT는 개념 참고용으로만 사용한다. Humble, Foxy, Gazebo Classic 명령은 Jazzy/Harmonic 실습 명령으로 교체한 뒤 배포한다.
- 실기기 연결 실패가 20분 안에 해결되지 않으면 해당 조는 시뮬레이션 트랙으로 전환하고, 강사가 별도 장비 점검표에 원인을 기록한다.

- 실습 교육:
  - ROBOTIS 공식 Jazzy 패키지 빌드 및 패키지 목록 확인
  - `open_manipulator_x.launch.py` 실행 전 로봇 자세와 포트 확인

  - 하드웨어 미연결 조는 description/RViz2로 링크와 조인트 이름 확인

- 실습 산출물:
  - 장비별 USB 포트, DYNAMIXEL 연결, 컨트롤러 상태 점검표
  - 실제 로봇 또는 RViz2의 `/joint_states` 1회 캡처
  - 링크·조인트·컨트롤러 대응표

- 실습 교육:

  - GUI에서 현재 상태를 확인하고 미리 정한 안전 자세 실행
  - `/joint_states` 기록과 명령 후 오차 비교
  - Action 목록과 controller interface 조회
- 실습 자료:

  - `gong_ws/src/gong_basic/gong_basic/action_client.py`
- 실습 산출물:

  - 관절별 명령값·피드백값·완료 여부 표
  - 실기기 안전 운전 체크리스트

### Day 3. MoveIt 2 경로 계획과 하드웨어 실행 - 7월 29일

- 핵심 주제: MoveIt 2, SRDF, Planning Group, Named State, Planning Scene, IK, plan/execute, ROS 2 Action
- 이론 교육:
  - URDF와 SRDF의 역할 차이
  - `arm`과 `gripper` Planning Group
  - 현재 상태, 목표 상태, 충돌 검사, 경로 계획, 실행의 단계
  - ROS 1 `moveit_commander`와 ROS 2 MoveIt 2 API를 혼용하지 않는 기준
- 실습 교육:
  - OpenMANIPULATOR MoveIt launch와 RViz MotionPlanning 패널 실행
  - `init`, `home`, `open`, `close` Named State 확인
  - 계획만 실행한 뒤 궤적을 검토하고, 안전한 목표만 실기기에서 실행
  - 간단한 충돌 상자를 Planning Scene에 추가해 경로 변화 확인
- 실습 자료:
  - ROBOTIS OpenMANIPULATOR-X Operation 문서
  - MoveIt 2 Motion Planning Python API 및 Planning Scene 공식 예제
  - `doc/커리큘럼 개선 방향.pdf`
- 실습 산출물:
  - Named State 4종의 계획·실행 결과
  - 충돌체 유무에 따른 경로 비교 화면
  - planning 실패 원인과 해결 기록 1건 이상
- 확인 질문:
  - plan 성공과 execute 성공을 따로 확인해야 하는 이유는 무엇인가
  - IK 해가 없거나 충돌로 판정될 때 어떤 조건을 먼저 확인하는가
  - 실기기 실행 전 RViz의 start state가 실제 `/joint_states`와 일치해야 하는 이유는 무엇인가

## 강사용 체크포인트

---

- 월요일 수업 전 `doc/2주차_교육자료_확보_및_작동확인_안내.md`의 Gate A~D를 강사용 PC에서 통과한다.
- 기존 PPT의 `ros-humble-*`, `gazebo_ros`, Gazebo Classic, Foxy 명령은 화면에 그대로 노출하지 않는다.
- OpenMANIPULATOR 공식 저장소와 의존 저장소의 `jazzy` 브랜치 또는 확정 commit을 기록하고 전 교육생에게 같은 버전을 배포한다.
- 실기기별 DYNAMIXEL ID, baud rate, 포트, 시작 자세, 전원, 케이블 상태를 사진과 함께 기록한다.
- MoveIt 실행 전 `/joint_states` 수신과 controller 활성 상태를 확인한다.
- Gazebo 실행 후 창 표시만으로 성공 처리하지 않고 `/clock`, `/joint_states`, controller, 실제 동작까지 확인한다.
- 다수 조가 한 번에 실기기를 움직이지 않도록 장비별 운전 담당자 한 명과 비상 정지 담당자 한 명을 정한다.
- 자동 테스트는 현재 코드 스타일과 docstring 검사에서 실패하므로 “빌드 성공”과 “테스트 전체 통과”를 같은 의미로 기록하지 않는다.

## 추천 과제

---

- 두 Named State 사이의 왕복 동작을 Action 또는 MoveIt 2로 실행하고 시간·오차를 기록한다.
